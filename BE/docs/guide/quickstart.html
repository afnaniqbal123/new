Orientation

What this is

A boilerplate, not a product. Modules here are meant to be deleted as often as they are extended — if your project has no PayPal, delete paypal/. That expectation is why boundaries are enforced by tooling instead of by convention: deleting a module should never unpick three others.

It is also agent-first. The premise in the README is that most code here will be written by AI agents, and every architectural question left unanswered is one an agent re-answers from scratch on every task — differently each time. So the answers are decided once by people, written down in docs/architecture/, and enforced by lint rules and a ratcheted baseline.

The practical consequence

You rarely need to decide where code goes. There is a documented owner for every kind of change, and if you get it wrong the commit is blocked with the rule name, the offending import path, and the doc that explains it. Treat a blocked commit as architecture feedback, not an obstacle.

What you get out of the box

Identity & access

JWT access tokens (15 min) with rotating refresh sessions (60 days), OTP flows, password reset, Sign in with Apple, and CASL-based permissions with per-record and per-field rules.

Product surface

Users, chat rooms with a WebSocket gateway, notifications with an SSE stream, S3 media presigning, Handlebars email, OneSignal push.

Money

Stripe and PayPal side by side — payments, subscriptions, invoices, cards and signature-verified webhooks, each fully confined to its own module.

Guard rails

A six-stage pre-commit gate, 15 custom ESLint rules, a module-dependency checker, a documentation checker, and CI that runs all of it.

Setup

Get it running

You need Node 22, a MongoDB you can reach, and pnpm. Nothing else — there is no Docker Compose, no queue, no cache to start.

Activate the pinned pnpm

pnpm is the only supported package manager, and CI fails the build if a package-lock.json or yarn.lock appears. Corepack reads the exact version out of package.json.

corepack enable
pnpm install --frozen-lockfile

This also installs the Husky hooks via the prepare script — which is what puts the commit gate in place.

Create your .env

Copy the template, then fill in at minimum MONGODB_URI and JWT_SECRET. Everything else can stay empty until you touch the module that needs it.

cp .env.example .env
openssl rand -base64 48   # paste into JWT_SECRET

The app refuses to boot on a weak secret

validateAuthEnv runs at ConfigModule load and rejects a JWT_SECRET under 32 characters. That is deliberate — a short signing key is brute-forceable offline, and every token it ever signed would be forgeable. Better to fail at startup than at the first login.

Know which env file wins

Config resolves .env.<NODE_ENV> first and falls back to .env, with NODE_ENV defaulting to dev. So a stray .env.dev silently outranks your .env — worth checking first when a value looks ignored.

envFilePath: [`.env.${process.env.NODE_ENV ?? 'dev'}`, '.env']

Start it

pnpm run start:dev

Listens on PORT, defaulting to 8080. CORS is open in development.

Open the API docs

Swagger UI is mounted at /api-docs with bearer auth persisted between reloads — paste an access token once and every subsequent call carries it.

http://localhost:8080/api-docs

Seed, if you need data

pnpm run seed

Runs src/scripts/seed.ts. Scripts are the one place exempt from the shared-helper rules — they are applications in their own right.

The shape of the code

Anatomy of a module

Every feature module has the same skeleton, and the structure stage of the commit gate checks that folder names and file suffixes agree. user is the reference implementation — when in doubt, copy how it does something.

src/modules/user/
├── user.module.ts          wiring only — imports, providers, exports
├── user.controller.ts      HTTP: route, validate, map, delegate
├── user.service.ts         business behaviour + Mongoose calls
├── user.schema.ts          the collection this module owns
├── README.md               required for every new module
├── dto/                     request/response shapes, one class per file
│   └── update-user.dto.ts   must end in `Dto`
├── policies/                CASL rules about this module's records
│   └── user.policy.ts
└── constants/
    └── api-response/        every user-facing message, as an enum

Rules worth knowing before you write anything

  • Controllers never touch a model. nestjs/no-db-in-controller blocks an injected model in a controller.
  • No barrel files. index.ts re-exports are banned outright.
  • Cross-module imports are absolute — src/modules/..., never ../../.
  • Never import another module's schema. Needing its data means calling its service.
  • User-facing strings come from an api-response enum, not string literals at the call site.
  • Use @GetUser(), not @Req(). Raw request access is blocked.

Daily work

Your first endpoint

A worked example: a guarded GET /users/:id/summary. Every step below exists because a gate stage will ask for it — this is the shortest path that commits cleanly on the first try.

Add the messages to an enum

Hard-coded user-facing strings are blocked by nestjs/no-hardcoded-message.

// src/modules/user/constants/api-response/user.response.ts
export enum USER_RESPONSE {
  SUMMARY_FETCHED = 'User summary fetched successfully',
  NOT_FOUND = 'User not found',
}

Declare the DTO

Every field needs both an @ApiProperty() and a class-validator decorator — two separate rules enforce this. The class name must end in Dto.

// src/modules/user/dto/user-summary-query.dto.ts
export class UserSummaryQueryDto {
  @ApiProperty({ required: false, example: '30d' })
  @IsOptional()
  @IsIn(['7d', '30d'])
  window?: string;
}

Put the behaviour in the service

Errors go through SerializeHttpError so the response keeps the { data, status, message } envelope — raw throw new HttpException is blocked.

// src/modules/user/user.service.ts
async getSummary(id: string, ability: AppAbility) {
  const user = await this.userModel.findById(id).lean();
  if (!user) SerializeHttpError(null, 404, USER_RESPONSE.NOT_FOUND);

  // the record-level check — the route guard could not do this one
  this.authorization.assertCan(ability, Action.Read, subject(USER_SUBJECT, user));

  return buildSummary(user);
}

Wire the route

Authentication is already on — you do not add a guard for it. You add the permission.

// src/modules/user/user.controller.ts
@Get(':id/summary')
@RequirePermissions({ action: Action.Read, subject: USER_SUBJECT })
async summary(
  @Param('id') id: string,
  @Query() query: UserSummaryQueryDto,
  @GetAbility() ability: AppAbility,
) {
  const data = await this.userService.getSummary(id, ability);
  return SerializeHttpResponse(data, 200, USER_RESPONSE.SUMMARY_FETCHED);
}

The controller class already carries @ApiTags(), @ApiBearerAuth() and @UseGuards(OrganizationAccessGuard, PermissionsGuard) — a new controller needs all three, and two lint rules will tell you so.

Cover it with a policy test

Every policy needs five cases: allow, deny, ownership, elevated role, unknown role. src/modules/user/policies/user.policy.spec.ts is the reference.

If it's a new module, not a new route

Add a README.md in the module folder — the structure stage blocks a new module without one — register it in AppModule, and check the module map first to be sure the behaviour does not already have an owner.

Daily work

The response envelope

Every response is wrapped in the same three-field shape by src/utils/serializer.ts.

interface Serialized<T> { data: T; status: number; message: string; }

SerializeHttpResponse(data, 200, MESSAGE)  // returns the envelope
SerializeHttpError(null, 404, MESSAGE)      // throws HttpException with it

Known inconsistency — read this before integrating a client

Only the auth module returns real HTTP status codes. Everywhere else — chat, notifications, media, Stripe, PayPal — a failure comes back as HTTP 200 with the actual status inside the body. A refactor deliberately preserved those HTTP contracts rather than breaking every existing consumer.

So a client cannot trust the HTTP status outside /auth/* yet, and must read body.status there. New code should not treat this as two equally valid conventions — it is tracked debt, and the auth module shows the intended direction.

The guard rails

The commit gate

Hooks install themselves on pnpm install. Every stage runs even after an earlier one fails, so a blocked commit shows you the complete list of problems in one pass rather than one per attempt.

#StageChecksTypical
1Guard railsStaged .env files, hard-coded credentials, build output, files over 1 MB, merge-conflict markers<1s
2Lint & conventionseslint --fix and Prettier on staged files, then the strict gate: TypeScript correctness plus 15 nestjs/* rules2–5s
3Type safetytsc --noEmit across the project~2s
4StructureFile and folder naming, folder–suffix agreement, README for new modules<1s
5ArchitectureModule cycles, foreign schema reads, provider-SDK leakage — ratcheted against architecture-baseline.json<1s
6DocumentationRelative links resolve, Mermaid sanity check, ADR naming and fields, architecture index completeness<1s

Stage 2 fixes what it can — formatting, quote style, import order, every auto-fixable rule — and re-stages the result. You only ever see what needs a human decision.

The suppressions baseline

eslint-suppressions.json records violations that already existed when the gate was introduced. It is a ratchet: new and changed code must be fully clean, pre-existing violations do not block unrelated work, and the list can only shrink.

pnpm run debt                    # what is still baselined
pnpm run lint:baseline:prune     # drop suppressions now unused

Never run --suppress-all to make a failure go away

It re-suppresses your new violations along with the old ones, which is exactly what the ratchet exists to prevent.

When it blocks you

Every finding names the file, the line, what is wrong, the concrete fix, and the convention page that explains it.

claude "/fix-commit"   # have Claude apply the fixes

pnpm run lint          # or work through it yourself
pnpm run typecheck
pnpm run lint:check
pnpm run verify

Escape hatches

There is deliberately almost none. --no-verify skips every hook, but anything committed that way still fails CI — it buys minutes, not permission. A false positive on a secret takes quality-gate:allow on the line. A rule that is genuinely wrong for a case gets changed in tools/eslint-rules/, not disabled inline.

Testing

That the auth suites need no database is itself part of the contract. The authorization e2e asserts the user collection is read zero times across an authenticated request — so if authentication ever starts reading from the database again, however that read is spelled, this test fails. The lint rules are the fast feedback; that assertion is the real guarantee.

CI runs the gate, the checkers' own tests, unit tests, a build, and the auth contract on every push to main and every pull request.

Troubleshooting

SymptomCause and fix
App exits at startup complaining about the secretJWT_SECRET is missing or under 32 characters. openssl rand -base64 48.
An env value seems ignoredA .env.dev (or .env.<NODE_ENV>) is shadowing .env. It is first in the lookup order.
Hooks are not runningpnpm run prepare, then check git config core.hooksPath prints .husky/_.
A field you sent never reaches the handlerThe global pipe uses whitelist: true. Undeclared DTO properties are stripped. Add it to the DTO — with both decorators.
401 on a route you expected to be openAuthentication is on by default. Add @Public() — visibly, and only for pre-credential, signature-authenticated, or health routes.
403 from @GetOrganizationId()The route is missing @TenantScoped() and OrganizationAccessGuard. It fails closed rather than returning undefined, because an empty tenant filter means "everything".
A permission rule seems to be ignoredGuard ordering. Declare @UseGuards(OrganizationAccessGuard, PermissionsGuard) at controller level, in that order — Nest only respects ordering within a single @UseGuards.
Role change hasn't taken effectAbilities are built from token claims. It applies when the access token expires — up to 15 minutes. Revoke sessions to shorten that.
Commit blocked by architecture:checkYou crossed a module boundary. Read the named rule, then call the owning module's service instead of importing its internals.
An error returns HTTP 200Expected outside auth. Read body.status. Tracked debt.
